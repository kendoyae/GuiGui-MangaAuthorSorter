# V1.11.0 作者实体与在线解析 MVP 规则

## 目标

V1.11.0 在原有“字符串匹配作者目录”的基础上增加独立的作者实体层，并把联网查询限制在本地规则仍判定为“新作者 / 未解析”的身份。联网不是扫描文件的必经步骤，默认关闭；关闭时行为与 V1.10.26 的本地识别流程保持一致。

## 本地作者实体库

运行时数据文件：`AuthorEntities.json`。第一版使用 JSON 保存关系化结构，避免为当前 .NET Framework 4.8 / csc.exe 构建增加 SQLite 原生 DLL 或额外安装依赖。数据模型保留为可迁移结构：

- `Authors`：作者实体，包含标准名、罗马字名、E-Hentai artist tag、Danbooru artist tag、来源、外部 ID 与确认状态。
- `Aliases`：别名 → AuthorId，并记录别名类型和来源。
- `Circles`：社团实体，保留标准名、罗马字名及外部 group tag。
- `AuthorCircles`：作者 ↔ 社团关系。
- `LookupCache`：公共数据源查询缓存，记录 resolved / ambiguous / not_found / error。

本地 `AuthorAliases.txt` 继续保留，用户手工维护的别名优先级仍高于作者实体库；V1.11.0 不自动迁移或删除旧别名。

## 扫描顺序

1. 先执行 V1.10.26 的本地目录、标准化、别名、社团/作者结构化匹配。
2. 加载 `AuthorEntities.json`，使用标准名、罗马字名、外部 tag 和实体别名参与本地匹配。
3. 仍属于“新作者 / 未解析”的普通身份加入在线待解析队列。
4. 队列按标准化名称去重；不会对每一个文件单独发起网络请求。
5. 在线解析成功后写入当前会话实体索引；若启用“保存查询结果”，同时持久化到 `AuthorEntities.json`。
6. 至少解析出一个新实体时，对当前扫描结果重新规划一次，使新实体立即参与作者目录匹配和新作者命名。

## 第一版公共数据源

- Provider：Danbooru。
- 每次扫描默认最多联网查询 20 个去重身份，可设置 1–100。
- 相邻网络查询约间隔 1.1 秒，每次请求约 10 秒超时。
- 网络失败只影响在线解析，不中断本地扫描和现有归档计划。
- 扫描取消会同时请求终止当前网络请求。

## 自动采用规则

MVP 只接受“唯一且精确”的作者身份：

- 查询名与 Danbooru artist `name` 精确等价：可作为强匹配。
- 查询名与某一 `other_names` 精确等价：可作为强匹配。
- 只有 `group_name` 命中：不把社团自动当作者。
- 恰好 1 个强匹配：建立/更新 AuthorEntity，并允许重新匹配。
- 多于 1 个强匹配：记录为 `ambiguous`，不自动采用。
- 没有强匹配：记录为 `not_found`，不做罗马音相似、编辑距离或第一条结果猜测。

负结果和歧义结果默认 14 天内复用缓存，避免每次扫描重复查询；如果关闭持久化，缓存只保留在本次程序会话中。

## 作者实体参与目录匹配

实体库命中后，会使用该实体已知的所有身份名称去匹配真实作者目录。

- 唯一命中一个已有目录：状态为 `[ID] 实体匹配`。
- 同一个实体可命中多个真实作者目录：保持候选/人工选择，不自动选。
- 同一个名称在实体库里指向多个 AuthorId：保持歧义。
- 实体没有命中已有目录：仍按“新作者”规划，但优先使用实体的 CanonicalName 作为作者身份。

## 安全边界

- 在线作者解析默认关闭，用户需在“设置 → 在线作者解析...”主动启用。
- 只有待解析的作者身份文本会发送给公共数据源；本地文件路径、目标路径和文件内容不会作为该查询的一部分发送。
- 不因为外部结果修改、重命名现有作者目录。
- 不覆盖用户手工别名。
- 不做多数据源自动合并；V1.11.0 只有一个 Provider。
- 不使用模糊相似度决定作者身份。

## 后续扩展接口

公共数据源统一实现 `IAuthorProvider`：

```text
SearchAuthorAsync(query, cancellationToken)
```

后续可以新增其他 Provider，而不改变扫描主流程。等实体模型和冲突策略稳定后，再考虑 SQLite、多人共享公共库、自动更新和多数据源交叉验证。
