# 更新说明编写规则

`Docs/Changelog.zh-CN.md`、`Docs/Changelog.en-US.md`、`Docs/Changelog.de-DE.md` 和程序内“更新说明”面向普通用户，不是开发日志。三个官方语言版本必须同步维护；GitHub Release 正文使用中文、English、Deutsch 三语言分区。

## 必须遵守

- 每个版本优先控制在 3～8 条。
- 只说明用户能够感知的“新增了什么、修复了什么、改善了什么”。
- 使用短句和普通用户能理解的功能名称。
- 同一功能的一组内部改动合并成一条结果描述。
- 安全或兼容性变化应说明对用户的实际影响。

## 不应写入

- 类名、方法名、字段名、内部 Schema、缓存键或日志格式。
- 毫秒数、缓冲区大小、线程实现和布局计算等具体参数。
- 纯重构、目录移动、编译器参数等用户不可感知的实现细节。
- “保留上一版本全部功能”“未修改某某算法”等重复保证。

开发实现、参数和维护约束应写入代码注释、提交记录或 `Docs/` 专项文档。更新说明描述结果，不展开实现过程。
