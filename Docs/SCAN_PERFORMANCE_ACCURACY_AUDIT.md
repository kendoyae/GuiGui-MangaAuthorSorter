# 扫描性能与作者识别准确率审计（V1.11.22）

归归的核心优先级固定为：

1. 扫描响应必须快；
2. 作者识别必须准确；
3. 性能优化不得通过放宽自动匹配条件换取速度。

## V1.11.22 已修复的性能阻塞

### 1. Early Stop 前不再预读全部候选文件元数据

V1.11.21 的 `BuildPlanUntilMatches` 会先把全部 `FileInfo` 转成 `PlanItem`，过程中读取 `LastWriteTime` 与 `Length`，然后才进入 Early Stop。候选很多而目标数量很小时，这会抵消 Early Stop 的一部分收益。

V1.11.22 改为惰性枚举：只有真正进入作者识别的候选才读取文件元数据。

### 2. 不再重复读取同一文件元数据

V1.11.21 在 `BuildPlan` 创建初始 `PlanItem` 后，`ResolvePlan` 又重新创建 `FileInfo` 并再次读取时间/大小。

V1.11.22 复用已捕获的元数据，只保留执行规划前的存在性检查。

### 3. Everything 结果不再二次按修改时间排序

Everything 查询已经使用 `SortDateModifiedDescending`。V1.11.21 又读取所有候选的 `LastWriteTime` 并进行 LINQ 排序。

V1.11.22 直接保留 Everything 原生顺序，过滤不会改变相对顺序。

### 4. Everything 长路径缓冲区改为复用

V1.11.21 每个查询结果都新建一个 32768 字符的 `StringBuilder`。

V1.11.22 整个 Everything 结果循环复用同一个缓冲区，减少大批量候选时的内存分配与 GC 压力。

### 5. 扫描排除规则缓存同目录结果

Everything 返回文件列表时，文件夹级排除规则需要从文件父目录向上检查祖先目录。大量文件位于同一目录时，旧逻辑会重复构造相同的父目录链。

V1.11.22 按“扫描根目录 + 文件父目录”缓存文件夹排除结果；规则保存/刷新后立即清空缓存，不改变匹配语义。

### 6. 非“新作者”筛选不再做无意义的最终重建

筛选扫描完成后，只有“新作者”模式需要根据最终选中的结果重新计算新作者分组位置。

V1.11.22 中：

- 已匹配：直接使用分类结果；
- 歧义：直接使用分类结果；
- 未识别：直接使用分类结果；
- 新作者：保留最终重建，确保分组编号和目标路径准确。

## 当前仍可能影响扫描速度的因素

### 在线作者解析

在线解析默认关闭。启用后包含网络请求、服务端响应和请求间隔控制，耗时可能远高于本地扫描。它不应作为普通扫描的默认路径。

### 文件系统回退

Everything 不可用或 SDK 查询失败时，会递归访问实际文件系统。大量目录、机械硬盘、网络盘和杀毒软件实时扫描都会明显增加耗时。

### 超大型作者目录库

现有作者匹配为了保持语义清晰，会在若干匹配阶段遍历作者目录集合。作者文件夹达到非常大的数量级时，这会成为下一阶段主要 CPU 瓶颈。

后续若优化，应建立“规范化身份 -> 作者目录”的只读扫描期索引，并严格保持当前匹配优先级与歧义规则，不允许通过更宽松的模糊匹配换取速度。

### 首次 Everything SDK 获取

Everything 正在运行但官方 SDK DLL 缺失时，当前实现可能尝试获取 SDK。首次环境准备的网络耗时不代表正常扫描性能；正式发行时优先随分发包准备好所需 SDK，或将获取动作移出用户点击“扫描”后的关键路径。

## 作者识别准确率审计

V1.11.22 不修改作者识别判定语义。当前关键安全点：

- 用户手动指定 / 本地别名属于最高可信本地证据；
- 直接匹配和安全标准化优先于外部实体信息；
- 社团与作者分别命中不同文件夹时进入待确认，不自动猜测；
- 多个强候选不会静默选择其中一个；
- 谨慎标准化只产生候选，需要用户确认，不自动归档；
- `NormalizeLoose` 不删除内部空格或任意标点，避免把不同作者错误合并；
- 在线解析只处理新作者 / 未识别等待补充身份的项目，不覆盖已经明确的本地匹配；
- 在线证据链只在 IdentityScore 达到确认门槛且无硬冲突时写入实体，EH 为主身份源、NH 为辅助源；
- 用户自定义“标签清洗”和“扫描排除”规则可以主动改变输入范围，因此过宽的 Contains/Regex 规则仍需由用户负责确认。

## 后续性能修改原则

任何扫描性能优化必须满足：

- 不改变作者识别优先级；
- 不把“谨慎候选”升级为自动匹配；
- 不因为缓存而忽略本次扫描内新规划的作者目录；
- 不牺牲歧义检测；
- 缓存只能缓存确定性、在当前扫描上下文不变的数据；
- 新增索引时必须能返回全部候选，以保留“多个候选 -> 待确认”的行为。
