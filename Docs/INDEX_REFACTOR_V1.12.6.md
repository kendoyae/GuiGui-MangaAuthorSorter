# V1.12.6 — 真实扫描索引优化与阶段诊断

## 范围

这次只覆盖第一、二阶段：真实扫描分阶段诊断，以及目标作者索引增量更新。模拟文件名复杂度与 Everything 预热仍留待后续，不调整评分与作者/社团归类规则。

## 关键改变

- 每次 `ResolvePlanCore` 开始创建当前扫描的 `AuthorIndex`，使用既有数据初始化一次。
- 遇到新作者目标目录时，以 `AddRoundAuthorTarget` 构造 `AuthorFolder` 后调用 `AuthorIndex.AddPlannedFolder`：增量加入 Direct/Generic/Society/Creator/Segment/Cautious/Bigrams 等全部查询桶，而不再遍历全部已有作者。
- 别名映射与公共作者实体索引不发生扫描期变化，不重复重建。
- 新目录只有在路径第一次出现在本轮集合时才注册；相同姓名但不同目标路径仍可形成歧义。
- 此索引仅在单个规划线程中进行增量写入；并行候选预处理在增量修改开始前完成。禁止把该 API 用于无锁共享写入。

## 诊断含义

- `作者解析与匹配` 仍是整个真实扫描识别窗口的墙钟耗时。
- `身份来源准备`、`目标作者目录准备`、`目标索引首次构建`、`并行解析预处理`、`识别与目标规划循环`、`在线作者查询` 为不同的粗粒度阶段。
- `目标索引增量登记` **已经包含在** `识别与目标规划循环` 内，两项不可重复相加。
- `其他识别/缓存处理（差额）` 是未被以上粗粒度阶段覆盖的时间，例如持久化计划读取、分组、数据合并；不是独立 Stopwatch 测量。
- `唯一作者` 为解析出的不同作者身份数，`新建作者目录` 为本次真正登记的目录数量，二者不等于文件条目数。
- 诊断有非零记录才表明该次实际调用走过新的作者索引流程；纯缓存命中可没有构建记录。
- GL4 记录新增字段，保留 GL3 的读取兼容。

## 测试与限制

- `Build/RUN_INCREMENTAL_CONTRACT_TESTS.cmd` 新增逐项对比（40 次新增的索引）与全量重建结果，包括姓名歧义、别名、角色、候选 bigram 查询结果。
- 改动**不保证**真实扫描从 13 秒直接降到模拟 437 ms；新诊断用来找到剩余耗时和后续的优化优先级。
- 请在 Windows 实际执行 BUILD_EXE.cmd、合同测试，再用相同来源/目标文件集合重复测试并核验目标作者/歧义/新作者状态不变。
