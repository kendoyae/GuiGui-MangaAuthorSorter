# V1.12.8 归归增量扫描性能修正

## 1. Everything 成功但返回零结果

- Everything SDK 查询成功且当前目录有可确认的索引覆盖：使用空结果，不再重复遍历文件系统。
- 索引覆盖不确定（如未加入索引的网络位置、被 Everything 排除的位置）或 SDK 查询失败：继续使用原有文件系统回退，防止漏检。
- 校验只调用 Everything SDK 搜索目录自身并进行完整路径相等检查；校验失败不会被当成可信的空结果。

## 2. 整理计划缓存写入

- 全部结果都来自有效缓存时：不调用 `UpsertMigrationPlans`，避免全量写库。
- 部分文件变化时：只把本轮经识别引擎重新计算、且已登记 `FileId` 的计划行写入。
- 多行写入使用单事务和可复用的 SQLite 预编译语句，逐行绑定、执行、重置。
- 旧版本 `FileIndexCache.db`、解析结果和识别规则保持原样，无需手动删除缓存。

## 3. 诊断准确性

- 从内存预热快照返回时，本轮 `ProviderQueryMs` 和 `IndexReconcileMs` 必须为 0；源发现耗时只显示本轮获取并复制快照所花时间。
- 本轮缓存快照命中不能再把上一次 `FileIndexDelta` 算作本次新增、删除、移动或改名。
- 新增：`PlanCacheReadMs`（包含在作者解析与匹配时间内）、`PlanCacheWriteMs`（在扫描收尾阶段）、`FinalizeMs`（扫描收尾扣除计划写库时间）；不要把重叠项加总两次。
- 性能日志格式保持 GL4，新字段以 `PCR/PCW/FIN` 保存，旧日志仍可读取且缺失字段显示 0。

## 4. Windows 回归测试

执行：

```bat
BUILD_EXE.cmd
Build\RUN_INCREMENTAL_CONTRACT_TESTS.cmd
```

建议使用同一批 8,490 文件验证：

1. 未勾选子目录且直属文件为零：Everything 覆盖正常时不应花费秒级时间重新遍历目录树。
2. 首次勾选子目录：完整建立索引并识别 8,490 文件，新增计划进入 SQLite。
3. 不修改文件再次扫描：`重新计算=0`，`计划缓存写入=0 ms`。
4. 修改单个文件名再次扫描：只重新计算并写回该条，其他计划应保持不变。
5. 重启后再扫描：读取持久化缓存，无变化时重新识别为 0。
6. 将扫描位置换成 Everything 不索引的目录：必须安全回退，不能误显示为真实零结果。

说明：这里的 0 ms 表示无写入或低于 Stopwatch 毫秒计时精度，必须同时以写入调用次数核验真正的“零写入”。
