# 作者实体库：三页交互重构

这次调整仅涉及作者实体管理的 Windows WinForms 界面及导航，不改变 `AuthorEntities.json`、`GuiGuiAuthorIndex.db` 的保存结构或作者识别算法。

## 新入口

- **作者与社团**：一个搜索框搜索用户及公共作者 / 社团。默认展示用户实体；输入查询时按需同步展示公共库结果；切换“公共数据”可浏览公共库并分页。双击进入实体详情。用户实体可直接修改；公共实体修改调用现有 `SavePublicOverride`，公共数据库仍只读。
- **待确认**：原冲突管理与决定状态，沿用旧数据模型和确认接口。
- **数据维护**：用户导入/导出、手动刷新公共索引、原公共覆盖管理、在线查询缓存管理。公共覆盖 / 缓存以独立管理弹窗打开，不占据顶级标签页。
- **归档设置 → 文件夹名称规则**：独立规则管理弹窗，保持原规则存储和新增、修改、删除能力。规则不被自动转换成作者身份别名。

## 实体详情

查看正式名称、罗马字、用户或公共来源、别名、禁用名称、当前的提供方身份及现有社团关系。编辑按钮根据实体来源分别调用用户实体保存或公共数据用户覆盖；作者社团关系按钮进入关系管理弹窗。

* 公共作者第一次新建用户社团关系时，在确认保存后按需创建对应的公共用户覆盖，随后保留关系到用户数据中。
* 公共社团的原生关联仍由只读公共数据库提供；本次没有新增对公共社团关系的直接写入。
* 已有公共覆盖的重新绑定和恢复公共值在“数据维护 → 公共数据用户覆盖”继续保留。
* 只有选择用户实体才能使用“删除”；公共库条目不会被直接删除。

## 性能与兼容

公共索引可能很大，因此“全部来源”状态下没有搜索词时只显示用户数据；输入关键词后查询公共索引。公共数据按 200 条/页分页；文本输入使用 350 ms 防抖。

本次不提供旧版 UI 布局迁移。数据文件格式不变，已有作者身份、冲突记录、覆盖和缓存不迁移、不删除。

## 本次没有实现

- 从 nh-metadata-archive 下载 / 增量提取 CSV；
- 远程 GitHub `sources.json` 管理；
- 作品级证据表或自动交叉验证评分机制；
- nHentai API v2 和旧参考库的移除。

这些属于此前讨论的另一个“来源与证据层”开发阶段，本次 UI 重构未改变这些模块。详情窗口仅展示**当前真实保存的来源和身份信息**，不声称已有作品级证据。

## 验证

需在 Windows 上执行 `BUILD_EXE.cmd --no-pause` 编译 .NET Framework 4.8 WinForms 应用，并进行以下交互回归：

1. 用户实体（含同名）新增、编辑、删除、别名和禁用名处理；
2. 公共索引搜索、分页、只读原值和覆盖 / 还原；
3. 用户作者、公共作者与用户社团的关联、禁用和解除；
4. 冲突确认与公共身份重新绑定；
5. 规则新增、修改、删除，保存后扫描目标的命名影响；
6. 导入、导出、缓存清除和后台状态更新；
7. 简中、英文、德文及窄窗口布局；
8. `Tests/WindowNavigationTests.cs` 顶层标签数与主窗口非模态导航。
