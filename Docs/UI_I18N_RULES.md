# 归归全局多语言 UI 适配规范（V1.11.23）

本规范适用于主界面、二级窗口、设置页、DataGridView、菜单、Tab、工具栏、状态区、确认窗口及后续新增 UI。它是开发约束，不是翻译建议的可选项。

当前正式维护语言仅为 `zh-CN`、`en-US`、`de-DE`。所有新增界面文字、状态、提示和错误必须同时进入三份正式语言包及 `_template.json`，并保证 Key 与格式占位符完全一致；禁止在界面代码中直接硬编码任一语言的显示文本。多语言是全软件规范，不属于任何单独页面。

1. 禁止根据中文文本长度写死按钮、标签、表格列等控件宽度。
2. 普通按钮采用“固定高度 + 根据当前语言文本自动宽度 + 合理 Padding / MinimumWidth”，不得通过缩小字体或截断关键按钮文字解决空间不足。
3. DataGridView 中，“启用、状态、类型、规则类型、作用范围、匹配方式”等短枚举列使用 `AllCells` / 根据当前语言实际文字自动计算宽度；“名称、示例、路径、规则内容、规则说明”等长文本列使用 `Fill`，通过 `FillWeight` 分配剩余空间。
4. DataGridView 表头统一禁止换行，不能出现“作用范/围”“规则说/明”；普通单元格默认也不换行。长内容空间不足时使用省略显示，并通过 Tooltip、详情或编辑窗口查看完整内容。
5. 窗口缩小时优先压缩 Fill 类型的长文本列，短枚举列和关键操作文字必须保持完整；二级窗口应设置合理 `MinimumSize`，禁止缩小到控件重叠、表头换行或按钮文字被截断。
6. 设置页面和复杂表单优先使用 `TableLayoutPanel`、`FlowLayoutPanel`、`Dock`、`Anchor`、`AutoSize` 等动态布局，避免依赖固定坐标和固定 Label 宽度。
7. 提示句与操作按钮分离。例如“请选择原始位置”属于提示文字，按钮只保留“选择文件夹”，避免完整句子塞进按钮。
8. 菜单、Tab、工具栏、状态标签等同样不得基于中文写死宽度；关键短文本完整显示，路径、文件名、示例、说明等非关键长文本可以省略。
9. 运行时切换语言后，必须重新计算控件 PreferredSize、按钮宽度、DataGridView Auto 列与 Fill 列，并重新执行布局，不能只替换 `.Text`。当前版本切换语言会重启应用，因此重启后的完整 UI 重建等价执行该重算；若未来改成无重启切换，必须调用统一的本地化重布局入口。
10. 所有语言文件统一使用 UTF-8，禁止使用 `Encoding.Default` 等依赖系统代码页的读取方式。
11. 不限制翻译字符数，应以实际像素宽度和布局能力处理多语言文本；UI 翻译允许采用准确、自然的短译法，不要求机械逐字翻译。
12. 德文 `de-DE` 作为正式 UI 文本长度压力测试语言。每次新增或修改 UI，至少测试 `zh-CN 100% DPI`、`de-DE 100% DPI`、`de-DE 125% DPI`、`de-DE 150% DPI`，并测试默认窗口、较宽窗口和 MinimumSize 状态。
13. `de-DE` 为正式德语语言包，并兼作长文本压力测试语言。仓库不再保存 `LocalizationTests` / `qps-ploc` 测试语言包；如需额外伪本地化，只能临时生成，不进入源码包或发行包。
14. 禁止通过自动缩小字体来适配长语言；字体大小保持统一，应通过动态布局、控件宽度、换行策略和窗口尺寸解决。
15. 允许换行的主要是帮助说明、设置说明、警告正文、首次使用引导等长文本；按钮、菜单、状态、DataGridView 表头、短字段名原则上禁止换行。
16. “标签清洗规则”和“扫描排除规则”等现有页面必须遵循同一规范，尤其避免表格右侧存在大量空白、但“规则说明 / 规则内容 / 作用范围”等列仍过窄或发生换行。
17. 批量填充大型 DataGridView 时，必须临时冻结 `AllCells / Fill` 自动列宽，在批量写入结束后一次性恢复；禁止为每个新增行重复触发全表文本测量。
18. 正式语言翻译必须准确、自然、尽量短小精炼；“短译”优先于逐字直译，但不得丢失操作含义。
19. 新增或修改页面前必须同时阅读本文件与 `Docs/UI_STYLE_RULES.md`；完成后检查三种正式语言、DPI、最小尺寸、窗口拉伸和键集合一致性。

## V1.11.23 代码基线

- `UiStyle.NewButton`：参数宽度视为 MinimumWidth；实际宽度由当前字体与文本像素宽度计算。
- `UiStyle.ConfigureShortColumn`：短枚举列按当前语言自动宽度；主扫描列表批量填充时临时冻结自动列宽，填充完成后一次性恢复。
- `UiStyle.ConfigureFillColumn`：长文本列统一使用 `Fill + FillWeight + MinimumWidth`。
- `GridInteraction.Apply`：不再强行把所有列重置为 `None`，会保留页面声明的 `AllCells / Fill / None` 策略。
- `UiStyle.StyleGrid` / `GridInteraction.Apply`：强制表头与普通单元格默认 `WrapMode=False`。
- `UiStyle.FitComboBoxToItems`：需要显示完整选项的下拉框按当前语言实际项宽度计算。
- `UiStyle.RelayoutLocalizedTree`：为未来无重启语言切换提供统一重布局入口；当前语言切换重启后也会重新构建完整布局。

|---|---:|---|

| de-DE（正式） | 100% | 默认 / 较宽 / MinimumSize |
| de-DE（正式） | 125% | 默认 / 较宽 / MinimumSize |

测试重点：按钮完整、短枚举列完整、表头不换行、Tab/菜单不截断、长文本列合理压缩、无控件重叠、无固定中文宽度造成的异常空白。

## 文案语义精简原则（V1.11.23）

- 精简只删除冗余修饰词，不删除决定功能含义的核心名词，例如“方案 / 规则 / 解析 / 库”。
- 同一概念只使用一个 UI 字段或语言 Key；不得为了缩短单个文字而拆成两个重复字段解释同一件事。
- 导航/菜单名称优先“完整且短”，按钮优先“动作词”，说明文字才承担补充解释。
- 已废弃且无代码引用的导航语言 Key 应从正式 schema 删除，避免长期维护重复翻译。
