# 启动状态记忆与扫描结果恢复

数量（含 0＝不限）、扫描范围及扫描子目录在变更后立即保存到 UserSettings.ini；路径沿用原有设置存储，并在离开路径输入框、扫描和关闭时保存。设置通过同目录临时文件替换，避免写入中断破坏原配置。

FileIndexCache.db 的 DisplayedSession 元数据记录最后成功显示的扫描会话。启动先按当前识别规则与作者依赖读取该会话的 MigrationPlanCache，恢复文件、识别结果、状态、候选及目标预览；没有新增完整 JSON 快照。手动确认的目标目录、名称和作者也保存在计划行中，并在重新规划后写入受影响的行。

恢复列表标记为上次结果，校验完成前禁止整理。随后复用正常扫描工作线程同步磁盘索引，复用有效的逐文件结果，只重算变化或失效的文件。冷启动仍需由文件系统提供器检查目录；这里避免的是重复识别和完整结果重算，不保证完全不枚举目录。

源或目标不可访问时保留可恢复的列表并提示检查路径；缓存不可用时提示手动扫描。手动扫描保留并进入增量校验流程。增加数量或切换目录深度会自动补充查询；缩小数量及切换分类使用现有列表筛选。任何恢复、查询或校验均不自动执行文件迁移。

执行整理前再次检查源文件存在性、大小和修改时间，变化时要求重新扫描；目标冲突继续使用现有安全检查。当前选中行不恢复。旧版本没有记录 DisplayedSession 时，需要先成功扫描一次建立恢复入口。

验证：增量索引契约测试覆盖设置重启恢复、无上限和取消勾选、SQLite 会话重开恢复、手动确认字段、规则变化拒绝旧计划及局部写入保留其他行。完整构建与四份语言包校验通过。
