# V1.12.7 — 按需文件发现与索引元数据复用

- 关闭「扫描子目录」时，冷启动只查询当前目录；递归索引命中时可以直接投影，无二次发现。
- 递归与非递归索引使用不同的数据库作用域。非递归同步不能因为没有看到子目录文件就删除它们的记录或识别事实。
- 后续切换为递归时补齐此前未发现的目录；此时首次识别新增文件是正常行为。
- 正式 ArchiveEngine 构建计划时优先读取 `SourceIndexFileSnapshot` 的大小/修改时间，回退路径仍兼容文件系统扫描。
- 诊断新增文件提供器查询与 SQLite 文件索引同步耗时，写入现有 GL4 日志新字段 FQ / FS（旧记录保持兼容）。
- 当前目录零结果且未包含子目录时显示可点击提示。不会无依据声称子目录存在文件。
- 任何索引同步失败均不清空数据库；成功的文件发现结果仍可用于当前视图。需要在 Windows 执行 BUILD_EXE.cmd 和 Build\RUN_INCREMENTAL_CONTRACT_TESTS.cmd 验证。

## 性能与兼容性说明

- Everything 1.4+ 的 `parent:"..."` 原生查询限制为直属目录，递归仍使用原路径查询；从 Provider 端减少无关目录枚举。
- SQLite 大批量处理复用已准备的 upsert、ID 查找和作用域关联语句；保持原事务语义。
- 完整递归范围继续使用 V1.12.6 既有 SourceScope Key；仅浅层新增 `|Depth=Top`，以免升级后旧完整索引失去删除/迁移检测能力。
- 文件提供器查询、数据库同步耗时属于原先的文件发现范围内的子项，不应将这些耗时重复相加。
- 冷启动仅扫描当前目录时，数据库不会提前生成未知子目录的结果；勾选子目录后首次补齐数据库及识别是预期行为。
