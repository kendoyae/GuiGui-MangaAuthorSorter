# 扫描性能日志格式

性能诊断使用程序目录中的 `ScanPerformance.log`。勾选“记录性能诊断”时，每次完成正式扫描都会以 UTF-8（无 BOM）追加一条紧凑记录；后台预热本身不作为扫描记录写入。取消勾选不会删除已有历史。

当前格式版本为 `GL4`（兼容读取 `GL3`）。日志头示例：

```text
#GL4
#UNIT=ms; zero-duration fields omitted
2026-10-08T20:22:13.000|P=ESDK|H=0|RB=0|SH=0|FD=231|AM=1852|IB=9|PL=1588|IBC=1|IAC=482|UA=752|NA=482|IA=1633|RC=1562|TR=2279|C=1633|R=1562
```

`P=ESDK/SYS` 表示 Everything SDK / 文件系统；`H/RB/SH` 表示预热命中、点击前就绪及快照命中。性能耗时字段 `WW/SP/FD/AM/UI/TR` 分别为预热等待、快照准备、文件发现、作者识别与匹配、界面应用和总响应时间。

GL4 增加的诊断字段包括：`IS/TD/IB/II/PR/PL/OL`（身份准备、目标目录、目标索引首次构建与增量登记、并行预处理、规划、在线解析耗时）；`IBC/IAC/UA/NA`（首次构建数、增量登记数、不同作者数、新目录数）。`PH/PM/RH/RM/DH/DM` 记录缓存命中与未命中；`IC/IA/ID/IM/IV/IR` 记录文件索引复用、新增、移除、修改、移动、改名；`PC/RC` 记录计划缓存复用和重新计算数。`C/R` 分别是候选和结果数量。零耗时通常省略，读取时按 0 处理。

右侧历史扫描详情根据**左侧选中的历史记录**显示，不能被新发生的后台预热状态覆盖；只有没有选择历史记录时，才显示最新后台预热信息。复制报告也优先使用选中记录。

点击“清空记录”会同时重置内存和磁盘上的性能历史，保留 `GL4` 文件头。文件写入失败时应提示且不清理内存记录。日志不属于 `FileIndexCache.db`，不参与归档文件增量识别和缓存失效。
