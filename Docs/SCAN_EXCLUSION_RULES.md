# 全局扫描排除规则（V1.11.5 引入，V1.11.6 预览整合）

## 目标

扫描排除规则位于文件发现与作者识别之间，用来回答“这个文件/目录是否应该进入归档系统”。命中后直接跳过，不进入作者解析、作者/社团匹配、在线查询、归档预览或文件移动。

它与现有功能的职责不同：

- `ScanExclusionRules.json`：按名称模式全局跳过文件或文件夹。
- `ExclusionList.txt`：用户手工排除的具体文件完整路径。
- `TagCleaningRules.json`：文件已经进入识别流程后，清理 `[] / ［］ / 【】` 中不应作为作者身份的标签。
- 文件类型方案：决定哪些扩展名属于当前扫描方案。

## 设置入口

`设置 → 扫描排除规则...`

页面支持：

- 全局开关“扫描时启用全局排除规则”。
- 新增、编辑、删除、启用/停用规则。
- 恢复系统默认。
- 文件名 / 文件夹名两种作用范围。
- 包含、精确匹配、开头是、结尾是、高级正则表达式。
- 新增/编辑时实时测试一个文件名或文件夹名。

普通文字规则默认忽略英文大小写，因此 `AI Generated / AI GENERATED / ai generated` 会视为同一命中。

## 系统默认规则

系统只提供两个克制的示例规则，并且**默认关闭**：

1. `AI Generated`：文件名包含 `AI Generated`。
2. `AI 生成作品`：文件名包含 `AI生成`。

升级后不会因为新增该功能而自动隐藏任何现有文件。用户需要自行启用默认示例或添加自己的规则。

## 文件夹排除

文件夹规则命中后，文件系统扫描会直接停止进入该子目录树。例如：

- 作用范围：文件夹名
- 匹配方式：精确匹配
- 规则内容：`@Recycle`

则 `@Recycle` 目录及其所有子目录不会进入后续扫描。这样可以避免逐个枚举其中的文件。

Everything SDK 模式下，Everything 已经返回的路径仍会在进入识别前执行同一套文件/文件夹规则过滤。

## 扫描进度与记录

规则排除项不会进入作者识别/规划阶段的确定进度总数。

V1.11.6 起，规则排除结果并入主窗口顶部状态筛选：

`已排除 N`

点击后直接在主列表查看本次命中的文件/文件夹；“全部”视图也可同时显示正常预览项与排除项。排除行会显示命中规则、作用范围和完整路径，但它们只是显示专用预览数据，不进入可执行归档计划，因此不会参与作者识别、在线查询或执行整理。

对于“文件夹命中后直接剪枝”的情况，记录的是被排除的目录本身；程序不会为了统计目录内部到底有多少文件而再次遍历它，因为那会抵消目录剪枝的性能收益。

## 配置文件

首次运行会自动创建：

`ScanExclusionRules.json`

Version 1 字段：

- `GlobalEnabled`
- `Rules[].Enabled`
- `Rules[].Name`
- `Rules[].Example`
- `Rules[].Scope`
- `Rules[].MatchType`
- `Rules[].Pattern`

自定义正则保存前会验证，运行时使用短超时，避免异常表达式拖慢大批量扫描。
