# 多标签 / 多作者 / 结构化识别规则（V1.10.26）

## 1. 文件名前置标签

- 连续位于文件名前部的 `[ ]`、`［ ］`、`【 】` 标签会依次解析。
- 汉化、翻译、DL版、活动编号等元数据标签继续过滤。
- 多个有效身份标签全部参与匹配，而不是只取第一个。
- 一旦进入正文，不再把后续标题中的普通方括号内容当作者身份。

示例：

`[雨の町] [あめのまち]芳澤かすみ[中国翻译]`

身份候选为：`雨の町`、`あめのまち`。

## 2. 社团 + 多作者结构

支持：

- `社团 (作者A, 作者B)`
- `社团 (作者A，作者B)`
- `社团 (作者A、作者B)`
- `社团 (作者A & 作者B)`
- `社团 (作者A / 作者B)`
- `社团 (作者A + 作者B)`

严格允许修复一个缺失的右括号，用于旧文件名输入错误。

匹配时：

1. 社团名作为独立社团候选；
2. 每位作者作为独立作者候选；
3. 全部候选最终只指向同一目录时才自动归档；
4. 指向不同目录时进入歧义/人工确认。

## 3. 角色感知目录索引

已有作者目录分别记录：

- 完整目录身份；
- 明确的社团部分；
- 明确的作者部分；
- 保守名称段。

例如 `あめのまち (すわっぷきのこ)` 会建立：

- 完整身份：`あめのまち (すわっぷきのこ)`
- 社团：`あめのまち`
- 作者：`すわっぷきのこ`

因此文件标签 `[あめのまち]` 会显示为“社团匹配”。

## 4. 保守名称段

旧目录如 `雨と棘 雨がっぱ少女群` 可拆成完整名称段：

- `雨と棘`
- `雨がっぱ少女群`

仅在 2～3 个由空白分隔的名称段、每段至少 2 字符、且每段包含日文/CJK字符时启用。

不会把 `John Smith`、`Some Circle` 等拉丁多词名称自动拆分，避免误匹配。

## 5. 结构格式标准化

`社团 (作者)` 与 `社团 作者` 只有在“社团”和“作者”两个显式部分完整一致、且整个已有目录名正好等于两部分组合时，才自动视为结构格式差异。

示例：

`青豆腐 (ねろましん)` ↔ `青豆腐 ねろましん`

状态显示为“标准化”。

该规则不是“删除全部空格”匹配，`John Smith` 与 `JohnSmith` 仍不会自动合并。

## 6. 冲突安全规则

- 多个前置身份标签命中不同目录：歧义。
- 社团候选与作者候选命中不同目录：歧义。
- 多位作者分别命中不同目录：歧义。
- 同一候选命中多个目录：歧义。
- 疑似标点差异仍沿用 V1.10.24 的人工确认规则。

## 7. 文件名前部的旧格式兼容

- 支持 `(作者或社团)标题` 形式，但只解析文件名最前部的一个完整圆括号身份。
- `(C93)` 等活动编号与 `(同人誌)` 等出版类型会先跳过，再解析紧随其后的身份。
- 支持活动编号后的 `社团 (作者)]`、`作者]` 等单个方括号缺失格式。
- 支持 `[社团 (作者)` 缺少右方括号但圆括号完整的格式。
- 支持拉丁社团名紧接括号信息的前缀，例如 `Xration (mil) ...` 提取 `Xration (mil)`。
- 所有兼容规则仅作用于文件名前部，不扫描标题正文中的普通括号，避免把作品标题或汉化组误认为作者。

## 8. 翻译标签、活动标签与作者标签链

- 文件名前部允许以空格、`+`、全角加号或斜线连接多个标签。
- 含“汉化 / 漢化 / 翻译 / 翻訳”等内容的标签作为翻译信息跳过，但不会终止后续作者识别。
- `(AC2)`、`(COMIC1☆15)` 等活动标签跳过后，继续读取紧随其后的作者或社团标签。
- 多个有效作者标签都会保留；如果分别命中不同作者目录，仍进入歧义确认。
- `ニジエ`、`Pixiv` 通常作为来源标签跳过；但如果它是文件名前部唯一可用身份，则保留为作者候选，避免把同名作者误判为未识别。

任何冲突都不以“第一个命中”为由自动选择。

## 9. 结构证据与疑似活动（V1.13.0）

- 参考 https://ehwiki.org/wiki/renaming 的 `(Convention) [Circle (Artist)] Title` 结构；无需预先知道展会名称。结构事实保留原文、前缀边界、社团、作者、标题、理由和置信度。
- 圆括号前缀紧接完整社团／作者结构时，疑似活动置信度为 90；活动命名模式为 85；同一扫描至少三个不同社团／作者组合为 80。重复同一组合不增加统计证据。
- 这些分数是字段分类证据，不是作者确认概率。疑似活动从候选及评分输入中排除；内部作者命中实体／目录时评分增加 30，原有身份冲突仍需确认。
- 非活动圆括号身份继续支持，连续身份字段都参与识别。用户已确认的同名作者身份优先于结构推断，手动指定目标仍保持最高优先级。
- 统计证据仅用于完整扫描；提前停止扫描不预读全量文件。统计不写入黑名单、清洗规则或别名库，每轮重新统计。
- 无可靠身份时保留待确认；联网开启后按作品标题查询。查询结果必须带作品标题来源证据，排除硬冲突，只作为待确认候选，不自动建立作者关系。作品标题候选使用现有查询缓存 `WorkTitle-v1`，14 天内可离线复用，不将作品名写入作者别名。
- 解析候选继续使用持久缓存，解析和识别规则版本升级为 6；语法事实另用有容量上限的内存缓存。统计结果在读取缓存之后应用，避免某一轮扫描污染其他轮次。
- 详情中的 `[structure]` 解释前缀分类依据、字段置信度、社团／作者字段以及最终身份。未知活动名称缺少结构或足够统计证据时不应凭空确认；未覆盖的非标准格式仍需用户判断。

验证入口：`Build/RUN_STRUCTURE_TESTS.cmd`，包含结构候选、两个识别模式、不同组合统计、未知作品、标题回退、缓存及用户确认覆盖。
