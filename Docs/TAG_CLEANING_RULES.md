# V1.11.4 标签清洗规则

## 可视化规则编辑器（V1.11.4）

新增/编辑规则时默认不再要求手写正则。用户可以直接选择：

- 完全等于
- 包含文字
- 以文字开头
- 以文字结尾
- 前缀 + 数字
- 数字日期 / 期号
- 中文 / 日文日期
- 高级：正则表达式

“前缀 + 数字”可以填写多个前缀并用 `|` 分隔，例如 `C|コミケ`，再设置 `1–4` 位数字。程序内部会自动生成匹配表达式，但主界面只显示可读说明。

编辑窗口提供实时测试。测试时只输入标签内部内容，例如 `C103` 或 `2014.11`，不要输入外层 `[]`。测试结果仅用于验证当前规则，不会保存。

旧版自定义正则仍保留，并自动显示为“高级：正则表达式”。V1.11.1–V1.11.3 的内置规则会按原匹配方式与规则内容自动补齐可视化编辑信息，无需恢复系统默认。


## 可读名称与示例（V1.11.3）

规则列表新增“规则名称”和“示例”两列。系统默认规则通过内部 `NameKey` 随当前语言显示可读名称，例如“数字日期 / 期号”“Comic Market 活动编号”；`Example` 仅用于向用户说明典型命中内容，不参与实际匹配。

V1.11.1 / V1.11.2 已经生成的 `TagCleaningRules.json` 没有 `NameKey / Name / Example` 字段时，程序会按“匹配方式 + 规则内容”自动识别旧版内置规则并补全可读信息，不要求用户点击“恢复系统默认”。用户自定义旧规则若没有示例，精确匹配/包含文字会以规则内容作为示例；正则规则保持空示例，等待用户自行补充。

编辑系统规则时，如果用户没有修改显示名称，则继续保留多语言 `NameKey`；如果主动改名，则转为用户自定义名称。规则名称和示例都不会影响清洗判断。

标签清洗位于“文件名前置标签提取”和“作者/社团匹配”之间。它只决定某个 `[] / ［］ / 【】` 标签是否允许成为作者身份候选，不会修改文件名、作者目录名、别名库或作者实体库。

## 处理顺序

```text
文件名
  ↓
提取连续前置标签
  ↓
TagCleaningRules.json
  ├─ 命中：跳过该标签，继续检查下一个前置标签
  └─ 未命中：进入作者/社团结构化识别
  ↓
已有目录 / 别名 / AuthorEntity / 在线解析
```

例如：

```text
[2014.11] [Warped Apple] ADRENALINE SHOT!.rar
```

`2014.11` 命中日期规则后被跳过，扫描继续读取 `Warped Apple`，不会因为第一个标签是日期而创建 `2014.11` 作者目录。

如果所有前置标签都被清洗，项目会进入“未识别”，而不是拿日期、版本、来源等噪声建立新作者。

## 规则类型

- `Exact`：整个标签完全一致时清洗，适合 `DL版`、`FANTIA版`、`ニジエ` 等固定标签。
- `Contains`：标签中包含指定文字时清洗，适合 `中国翻译`、`汉化` 等可能带附加说明的标签。
- `Regex`：正则表达式，适合日期、期号和活动编号。保存时会验证表达式。

## 系统默认

系统默认覆盖：

- 中国翻译 / 中文翻译 / 汉化 / 机翻 / AI 翻译等翻译信息；
- DL版 / WEB版 / 电子版 / FANTIA / FANBOX / Pixiv / ニジエ；
- 无修正 / 修正版 / 合刊 / 合集 / 原稿删除状态；
- `2014.11`、`18.07`、`2024-10-03` 等日期型标签；
- `C97`、`コミケ 103`、`COMITIA 121` 等活动编号。

系统默认**不会**使用“纯数字全部清洗”规则，因为 `774` 等数字字符串可能是真实作者名。

## 用户规则

在 `设置 → 标签清洗规则...` 中可新增、编辑、删除和停用规则。点击“恢复系统默认”会把当前编辑列表替换为内置规则；只有点击“保存”后才写入 `TagCleaningRules.json`。

用户规则与系统规则使用同一条识别链，因此命中的噪声标签既不会进入本地作者匹配，也不会进入在线作者查询。

## 安全边界

标签清洗不是模糊识别系统。它不负责猜测真正作者，也不会把标题反推成作者；它只负责阻止明确的非作者标签进入后续身份解析。对于不确定的汉化组、发布组或特殊来源，建议用户添加“精确匹配”规则，而不是增加过宽的关键词。

E-Hentai Provider 不属于 V1.11.4 的实现范围，后续单独接入。
