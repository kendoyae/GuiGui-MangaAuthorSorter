归归 / MangaAuthorSorter V1.11.24

V1.11.24 性能诊断与统一 UI 规范
- 首页取消文件类型方案选择；“设置 → 文件类型方案”仍可新增、编辑和维护任意后缀，扫描使用设置中当前保存的方案。
- 主列表自适应完成后支持手工拖动列宽，并继续记忆用户调整结果。
- 其他设置、规则、历史和工具列表也统一支持拖动并记忆列宽。
- 所有列表增加清晰的纵向列分隔线；归档设置的输入框会完整填充右侧可用空间。
- 归档设置的上下编辑区按当前语言共享标签列宽；文件类型方案页面明确说明其扫描筛选作用和生效时机。
- 顶部状态筛选和搜索不再重建、重排单元格内容；扫描结果只在数据变化时构建一次，后续切换复用行缓存并批量替换当前可见集合。
- 筛选切换不再逐行修改 Visible，也不再同步重复检查成千上万个源/目标文件；短列宽只在完整预览变化时测量，改善数千到上万结果时的切换延迟与假死问题。
- 恢复被过度缩短的设置菜单名称：文件类型方案、标签清洗规则、扫描排除规则、在线作者解析、作者别名库、检查语言包。
- 文案精简规则调整为“一个概念一个字段；保留决定功能含义的核心词”，并清理无引用的旧导航 Key、合并重复的待确认动作 Key。
- 语言包 schema 升级至 37；zh-CN / en-US / de-DE / 模板保持相同 Key 集合与占位符。
- V1.11.22 的设置布局、Early Stop、Everything 元数据和排除缓存优化全部保留；作者识别判定语义未修改。

V1.11.8 详情固定骨架与多语言规则
- 右侧“处理预览”固定为 7 个永久信息位置：文件名 → 状态 → 识别作者 → 匹配作者 → 处理方式 → 目标位置 → 处理结果；切换不同状态时不再增删字段，空值统一显示“—”。
- 状态、识别作者、匹配作者、处理方式、目标位置采用统一两列结构；标签列宽根据当前语言这些固定标签的最大首选宽度自动计算，并限制在合理范围，内容列自动占用剩余宽度。
- 固定标签禁止换行；文件名、目标位置、处理结果使用固定两行高度与省略显示，鼠标悬停仍可查看完整源/目标路径。
- 底部两个操作按钮槽位永久保留，只切换按钮文字与启用状态，不再因状态变化产生位置跳动；已排除项目左侧进入“管理排除规则...”，右侧显示禁用的“已排除”。
- “无需处理”语义取消，统一使用明确的处理结果：可直接整理、将创建作者文件夹、需要确认作者、需要指定作者或跳过、不会参与整理、需要处理同名文件、无需移动。
- 歧义固定显示“匹配作者：多个候选 / 处理方式：等待用户确认”；未识别固定显示“等待用户指定”；已排除固定显示“跳过”，排除规则名合并在固定“处理结果”字段中。
- Languages/README.txt 新增 UI 翻译规则：标签应标准且简洁、按钮使用短操作文案、固定标签保持单行、不要逐字直译成长句，并建议在 100% / 125% / 150% DPI 下检查本地化布局。

V1.11.6 排除视图与扫描数量 Early Stop
- 全局扫描排除结果并入主界面顶部状态筛选，新增“已排除 N”；点击后直接使用主列表查看，不再占用底部独立“规则排除”入口。
- “全部”视图同时显示正常预览项与本次规则排除项；排除行显示命中规则与作用范围，但不会进入作者识别、在线查询、目标规划、执行整理或历史移动记录。
- 文件夹排除继续按 V1.11.5 逻辑直接剪枝，列表只记录命中的目录本身，不为了统计内部文件而重新遍历。
- 扫描数量在“已匹配 / 新作者 / 歧义 / 未识别”模式下改为目标结果数：本地分类达到目标后立即停止后续作者识别与规划，不再先完整识别整个候选集再截断结果。
- Early Stop 仍会先进行轻量候选枚举以保持“最新 → 最旧”顺序和统一应用全局排除规则；真正有成本的作者识别/目标规划只处理找到目标结果所需的前缀。
- 开启实时在线作者查询时，为避免在线结果改变本地分类，程序按递增候选前缀分批解析并尽早停止，而不是无条件完整分类全部文件。
- Early Stop 进度显示“已找到 X / 目标；已检查 Y 个候选文件”，扫描结束状态同时显示候选总量、实际识别数量和排除数量。

V1.11.5 全局扫描排除规则
- 新增“设置 → 扫描排除规则...”，用于在作者解析之前按文件名或文件夹名直接跳过不需要进入系统的内容。
- 支持文件名 / 文件夹名两种作用范围，以及包含、精确匹配、开头是、结尾是、高级正则表达式。普通文字规则默认忽略英文大小写。
- 文件夹规则命中后，文件系统扫描会直接剪枝整个子目录树，不再逐文件进入作者识别。
- 系统默认仅提供“AI Generated”“AI生成”两条示例规则，并保持关闭，避免升级后自动隐藏用户文件。
- 排除项不进入作者识别、在线查询、归档预览或移动；确定进度总数只计算真正进入识别的文件。
- V1.11.5 初版在底部显示“规则排除：N”；V1.11.6 起已并入顶部“已排除 N”状态筛选并共用主列表。
- 规则保存在 `ScanExclusionRules.json`；支持全局开关、恢复系统默认和实时测试。

V1.11.2 标签清洗规则管理（保留 V1.11.0 全部核心功能）
- 文件名前置 `[] / ［］ / 【】` 标签在进入作者匹配前先经过可配置的“标签清洗规则”；日期、版本、翻译信息、来源、活动编号等明显非作者标签会被跳过。
- 默认新增日期/期号规则，例如 `[2014.11]`、`[18.07]`、`[20.11]` 不再直接被当成作者；如果后面仍有有效前置标签，会继续识别后续标签。
- 默认清洗 `FANTIA版 / FANBOX版 / Pixiv / ニジエ / DL版 / WEB版 / 合刊 / 原稿已删除` 等常见版本、来源或状态标签；不会用“纯数字”规则误伤 `774` 之类可能真实存在的作者名。
- 新增“设置 → 标签清洗规则...”：可新增、编辑、删除、启用/停用规则；支持“精确匹配 / 包含文字 / 正则表达式”三种规则类型。
- 新增“恢复系统默认”按钮；恢复操作先回到内置规则列表，保存后写入 `TagCleaningRules.json`。
- 用户自定义清洗规则与系统规则统一作用于本地作者识别和当前在线作者查询入口，命中的噪声标签不会被发送给在线 Provider。
- 清洗只影响“这个标签能否成为作者候选”，不会修改真实文件名、作者目录名或已有别名/实体数据。
- E-Hentai Provider 本版暂不接入，后续单独处理；V1.11.0 现有在线作者模块保持兼容。

V1.11.0 作者实体与在线解析 MVP（保留 V1.10.26 全部核心功能）

V1.10.24 作者目录名称容错标准化（保留 V1.10.23 全部核心功能）
